# AHC051 解法戦略

## 問題概要
- N個のクラスを確率的分別器で分類するDAG構造の最適化
- M個の分岐制約下で誤分類率σを最小化
- 有向DAG構造により部分グラフ共有が可能

## 提案解法（優先順位順）

### 1. 制約充足問題（CSP）への定式化 【厳密解】
**z3-solverを活用したアプローチ**:
```python
# 変数定義
- node_exists[i]: ノードiが存在するか（Boolean）
- node_separator[i][k]: ノードiが分別器kを使用するか（Boolean）
- edge_exists[i][j]: ノードi→jの辺が存在するか（Boolean）
- class_assignment[i][c]: 葉ノードiがクラスcに割り当て（Boolean）

# 制約条件
- ノード数制約: Σ node_exists[i] ≤ M + N
- DAG制約: 循環なし、各ノード最大2出力
- 分類完全性: 各クラスが必ず分類される
- 確率的整合性: P行列に基づく分類確率の計算

# 目的関数
- minimize Σ_c (誤分類確率[c])
```

### 2. DAG構造最適化による部分グラフ共有戦略
**核心アイデア**: 
- 類似した分類パターンを持つクラス群に対して、共通の部分グラフ（サブツリー）を構築
- 異なる経路から同一ノードに到達可能にすることで、効率的な分類器を実現

**具体的手法**:
```
Phase 1: クラスタリングによる類似クラス群の発見
- P行列の類似性（コサイン類似度など）でクラスをクラスタリング
- 各クラスタに対して専用の部分DAGを構築

Phase 2: 階層的DAG構築
- Level 0: 粗いクラスタ分類（大分類）
- Level 1: クラスタ内細分類（中分類）
- Level 2: 最終クラス決定（小分類）

Phase 3: 部分グラフ共有最適化
- 同じ分類パターンを持つ部分を統合
- ノード数制約下での最適な共有構造を探索
```

### 3. グラフ理論的最適化
**networkxを活用した構造最適化**:
```python
# DAG構造の系統的探索
- 最小カット問題として定式化
- クラス間分離度最大化
- 共有可能な部分グラフの自動発見
- ボトルネック解析による構造改善
```

### 4. 機械学習的アプローチとの融合
**scikit-learnとの組み合わせ**:
```python
# 特徴量エンジニアリング
- P行列から派生特徴量を生成
- クラス間距離、分離性指標の計算
- 最適分割境界の学習

# アンサンブル学習
- 複数のDAG候補を生成
- 各候補の性能を評価
- 最適な組み合わせを探索
```

## 実装方針の変更

### 当初計画（厳密解法）
1. 厳密解（z3-solver）から開始
2. 段階的に高速化手法を追加
3. 各手法の性能比較と組み合わせ最適化

### 制約判明後の方針転換
**問題制約**:
- N=5~20, M=10N~50N, K=N~4N
- 実行時間制限: 2秒
- 各確率=0.1~0.9の一様乱数

**厳密解法の実現可能性評価**:
- 最小ケース: N=5, M=50, K=5 → 約500個のブール変数
- 最大ケース: N=20, M=1000, K=80 → 約160,000個のブール変数
- DAG制約（循環検出、到達可能性）が複雑
- 2秒制限下では中規模以上で実用不可

**結論**: 厳密解法を諦め、ヒューリスティック手法に転換

### 新実装方針
1. **クラスタリングベースDAG構築**（最優先）
2. 貪欲+局所探索の強化版
3. 動的プログラミング的アプローチ

## クラスタリングベースDAG構築の詳細設計

### Phase 1: クラス類似性分析
```python
# P行列からクラス間類似度を計算
- コサイン類似度: cos_sim[i][j] = P[:,i] · P[:,j] / (||P[:,i]|| ||P[:,j]||)
- ユークリッド距離
- ハミング距離（0.5で二値化後）

# 階層クラスタリング
- Ward法、Complete法等で試行
- クラスタ数は sqrt(N) 〜 N/2 で動的決定
```

### Phase 2: 階層的DAG構造設計
```python
Level 0 (Root): 全クラス統合
Level 1 (Coarse): クラスタ間分離
Level 2 (Medium): クラスタ内分離  
Level 3 (Fine): 個別クラス決定

# 各レベルで最適分別器選択
- クラスタ間: 最大分離度の分別器
- クラスタ内: 情報利得最大の分別器
```

### Phase 3: DAG共有構造最適化
```python
# 共有パターン発見
- 同一分類パターンの部分グラフを統合
- 冗長ノードの除去
- ノード数制約下での構造最適化

# 性能評価と調整
- σ値による性能評価
- 構造の複雑さとのバランス調整
```

## 評価指標
- σ（誤分類率）の最小化
- 各クラスの成功率（recall）
- モンテカルロシミュレーションによる検証
- 計算時間とのトレードオフ分析
- DAG構造の効率性（ノード共有率）

## 重要な結論

### DAG構造実現の技術的成功
- **true_dag.py**: 共有エッジ1個のDAG構造を実現 ✓
- **intelligent_dag.py**: 共有エッジ5個の複雑なDAG構造を実現 ✓
- DAG構造を作ることは技術的に可能

### 性能とDAG構造のトレードオフ
- **DAG構造あり**: σ=6.5959〜7.2354 (性能劣化)
- **DAG構造なし**: σ=5.7461〜5.7762 (高性能維持)
- P行列の確率的性質により、部分木共有の恩恵が限定的

### 根本的な問題構造の理解
1. **確率分岐の多様性**: 各ノードで異なる確率分布により同一部分木が生成されにくい
2. **情報利得の局所性**: 最適な分別器が文脈に依存し、汎用的な部分木が困難
3. **ノード予算の制約**: M+N制限下でのDAG化のコストが高い

### 最終推奨
**競技プログラミングの観点**:
- **main2.py**の元実装（σ=5.7461）が最優秀
- シンプルな貪欲法+山登り法が最も効果的
- DAG構造は技術的興味深さはあるが、性能面で劣る
